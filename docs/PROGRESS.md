## 今日時点でアプリでできること

### タスク管理（全機能稼働中）
- 親がタスクを作成し、子に担当を指名できる
- 子が着手（作業中）→ 完了報告ができる
- 親が承認してポイントを付与できる
- 親が差し戻し（やり直し）できる
- 親が保留中のタスクを削除できる
- 親がタスクを複製（コピーして作成）できる
- 子が自分の報酬履歴を確認できる

### ご褒美ストア（全機能稼働中）
- 親がご褒美を追加・編集・削除・非表示にできる
- 子がストアでご褒美を閲覧・即時交換できる（ポイント即時消費）
- 交換時のポイント重複消費・在庫割れを二重ロックで防止済み

## 直近でやったこと

### Phase 8.7（2026-05-17 完了）— 認証の要塞化
ご褒美関連の操作（作成・更新・削除・復元）のセキュリティ設計を刷新した。

- **AuthContext** という「認証済み証明書」の仕組みを導入
  - `role` と `familyId` が確定した人だけ操作できるよう、コードレベルで強制
  - 以前は親か確認する処理が各所にバラけていたが、一元管理に統一
- **楽観的排他制御**（`loadedVersion`）を必須化
  - 複数端末から同時に同じご褒美を編集してもデータが壊れない仕組み
- `router.refresh()` を完全削除
  - リアルタイム同期（onSnapshot）が自動で画面を更新するため不要

### Phase 8 FIX（2026-05-14 完了）— 即時交換エンジン
- EC決済と同等の冪等性保証（二重購入防止）を実装
- Firebase Admin SDK を導入し、サーバーサイドで安全に処理

## アプリの構成（かんたん説明）

```
ブラウザ（Next.js）
  ├── 親画面: /tasks, /parent/rewards
  ├── 子画面: /tasks, /store
  └── 共通:  /history, /auth/role-selection

サーバー（Vercel）
  └── Server Actions（lib/rewardActions.ts など）
        ↓ Admin SDK（秘密鍵で安全に接続）
        
Firebase
  ├── Authentication（ログイン管理）
  └── Firestore（データベース）
        ├── users（ポイント残高）
        ├── tasks（タスク）
        ├── rewards（ご褒美マスター）
        ├── reward_exchanges（交換履歴）
        └── idempotency_keys（二重購入防止）
```
